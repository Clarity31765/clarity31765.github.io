A Nelson rules checker for QC control charts

A single point beyond 3σ is easy to spot. Slow shifts and drifts are not, and those usually point to a real cause.

By Oliver Lee, October 2026

A small Python tool that applies all eight Nelson rules to an Individuals (I) control chart and marks the samples that break them.

I wrote it to check daily QC results in a trace-analysis lab (for example, an ICP-MS check standard run every day). A single point beyond 3σ is easy to spot by eye. Slow shifts and drifts are not, and those are the ones that usually point to a real cause: a new standard lot, cone or tubing wear, a change in the rinse.

What it does

  1. Reads a CSV of results in run order.
  2. Sets the center line and σ from a baseline period, using MR̄ / 1.128 (the usual estimate for an Individuals chart). You can also enter a fixed mean and σ from your own method validation.
  3. Checks every point against the eight rules.
  4. Writes violations.csv and control_chart.png.
Rule Pattern What it often means in a lab
1 1 point beyond 3σ Gross error: contamination, wrong dilution, vial mix-up
2 9 in a row on one side of the center line Shift: new standard or reagent lot, recalibration
3 6 in a row steadily up or down Drift: cone or tubing wear, standard degrading
4 14 in a row alternating up and down Over-adjustment, or two instruments/analysts alternating
5 2 of 3 beyond 2σ, same side Early sign of a shift
6 4 of 5 beyond 1σ, same side Small but sustained shift
7 15 in a row within 1σ Variation too small: wrong σ, or mixed data sources
8 8 in a row beyond 1σ, both sides Mixture of two populations

Rule wording follows Nelson (1984), as summarized in the references below.

Get the code

The tool is four small files: nelson_rules.py, test_nelson_rules.py, make_sample_data.py and data/sample_qc.csv.

Quick start

pip install numpy pandas matplotlib
    python make_sample_data.py                                   # synthetic data only
    python nelson_rules.py data/sample_qc.csv --baseline 25
    python test_nelson_rules.py                                  # one test per rule

Output for the sample data:

Center line = 9.9930, sigma = 0.1847 (MR-bar/1.128 from first 25 points)
    4 pattern(s) found
      sample  34  Rule 6: 4 of 5 points beyond 1 sigma, same side  [31-34]
      sample  35  Rule 2: 9 points in a row on the same side of the center line  [27-35]
      sample  51  Rule 3: 6 points in a row steadily increasing or decreasing  [46-51]
      sample  58  Rule 1: 1 point beyond 3 sigma  [58-58]

The sample data has three planted problems: a shift at samples 31–40, a drift at 46–51, and an outlier at 58. All three are found. The shift is caught by Rule 6 at sample 34, a point that is still inside 2σ and would pass a simple limit check.

Notes and limits

  • The data is synthetic. No company or customer data is used anywhere in this repository.
  • σ comes from the baseline. If the baseline already contains a problem, the limits will be too wide. For a validated method, use --mean and --sigma.
  • Running all eight rules raises the false-alarm rate. In practice a lab often picks the rules that match its known failure modes, and writes down the response for each one.
  • Each pattern is reported at the first point where it is complete, not again for every following point.

How this was built

I used an AI assistant (Claude) to draft the code. I then checked each rule against published definitions and wrote one hand-made test case per rule, including cases that must not trigger (8 points on one side is not Rule 2; 8 points beyond 1σ on one side only is not Rule 8).
