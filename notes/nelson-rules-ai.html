Two readings of the same control chart

A 3σ check finds one bad day. The Nelson rules find the shift 24 days earlier.

By Oliver Lee, November 2026

Here are 65 days of a daily check standard. The data is invented, but the problems in it are the usual ones: a shift, a slow drift, and one bad result.

Reading 1: limits only

If the only question is "is any point outside ±3σ?", one day is flagged: day 58. The shift that started on day 31 and the drift on days 46–51 pass without comment.

Reading 2: with the Nelson rules

DayRuleWhat it found
3464 of 5 points beyond 1σ above the line. The shift is caught four days after it starts, while every point is still inside 2σ.
352Nine days in a row above the line. The same shift, now confirmed.
513Six results in a row moving one way: the drift.
581The single bad result.

The rules found the shift 24 days before the only point that breaks a limit.

All charts use invented data for a check standard with a nominal value of 10 and σ = 0.2. Every example was run through the Nelson rules checker to confirm that it triggers its own rule and no other.

Handing the reading to AI

The table above is what the checker prints. Someone still has to say what it means, check the logbook, and write it down. Here is how that work splits in my process.

StepDone byWhy
Find the patternsCodeCounting must be exact and repeatable. One test per rule.
Summarize the flagsAI, checked by meFast, and easy to verify against the chart
Match flags to the logAI suggests, I decideGood at lining up dates; it does not know what happened in the lab
Write the note for QA or the customerAI drafts, I editSame finding, different readers and languages
Decide cause and actionMeNeeds the lab, the instrument and accountability

The split follows the evidence. In an exploratory study of ChatGPT on SPC tasks, Megahed and co-authors found it did well on structured work such as translating code, and explained well-known ideas reasonably. It also produced code that would not run, mixed up less common SPC terms, gave different answers to the same prompt, and invented a description for a dataset that does not exist. Their advice was to validate everything and use it alongside other methods.

So the rule check itself stays in deterministic code with one test per rule. The model works on the output of that code, where a wrong sentence is easy to catch against the chart.

Choosing rules

More rules are not always better. With normally distributed data, Rule 1 alone gives a false alarm about once every 370 points. Champ and Woodall showed that running the four Western Electric rules together raises that to about once every 92 points. Minitab's own guidance says the same thing in plain words: do not simply switch on every test. Pick the rules that match the failure modes you actually see, and write down the response for each.
