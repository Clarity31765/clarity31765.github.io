Two readings of the same control chart

A 3σ check finds one bad day. All eight Nelson rules find the shift 24 days earlier, and AI sorts the extra alarms.

By Oliver Lee, November 2026

Here are 65 days of a daily check standard. The data is invented, but the problems in it are the usual ones: a shift, a slow drift, and one bad result.

Reading 1: limits only

If the only question is "is any point outside ±3σ?", one day is flagged: day 58. The shift that started on day 31 and the drift on days 46–51 pass without comment.

Reading 2: all eight Nelson rules

DayRuleWhat it found
3464 of 5 points beyond 1σ above the line. The shift is caught four days after it starts, while every point is still inside 2σ.
352Nine days in a row above the line. The same shift, now confirmed.
513Six results in a row moving one way: the drift.
581The single bad result.

The full rule set found the shift 24 days before the only point that breaks a limit. That is the reason to use it: a 3σ limit reacts fast to large changes but is slow to notice small ones, and the extra run rules were added to catch small, sustained shifts early.

The catch: more rules, more alarms

Every rule you add also fires on normal data now and then. With normally distributed data, the 3σ limit alone gives a false alarm about once every 370 points. Adding the Western Electric run rules brings that down to roughly once every 92 to 95 points, depending on how the rules are counted. Minitab's guidance warns against switching on every test for this reason.

The usual answer is to run fewer rules. That gives back the early warning. My answer is to keep all eight rules on and change who sorts the alarms.

All charts use invented data for a check standard with a nominal value of 10 and σ = 0.2. Every example was run through the Nelson rules checker to confirm that it triggers its own rule and no other.

When the data breaks the chart

Every chart above assumes three things: each result is a number, each result is independent of the one before, and each element can be watched on its own. Trace-metal data often breaks all three. Below is one synthetic case for each, with the method I use instead. All numbers come from beyond_rules.py and can be rerun.

1. Most results are below the detection limit

LEFT-CENSORED DATA

Fe in a daily process blank, LOD 0.05 ppb. About 80% of results come back as "<LOD". The common shortcut writes each one as LOD/2 and then computes mean + 3 SD. That treats a guess as a measurement, and the limit follows the guess.

At the substituted limit, a clean blank would flag about once every 40 days instead of about once every 740, and a team soon stops reading those alarms. Published work makes the same point: with heavy censoring (above about 70%), standard monitoring methods are not appropriate, and the way "≤ LOQ" results are handled changes both the 3σ limits and Ppk.

2. One result depends on the last

AUTOCORRELATION

A daily check standard where part of each day's error carries into the next: slow sensitivity drift, a blank that changes over days. The process here is in control the whole time, so every alarm is false. But the moving range only sees day-to-day change, so σ comes out too small and the limits too tight.

The residual chart removes about nine in ten false alarms. It does not reach the independent-data level, because φ is estimated from only 50 days, and estimation error in the time-series model is known to inflate false alarms. Bootstrap-designed limits are one published fix; I note it here and do not use it.

3. Elements that move together

MULTIVARIATE

Fe, Cr and Ni in the same check sample. Stainless-type contamination raises all three together, so they are strongly correlated. On day 70, Fe rises alone: +2.7σ, while Cr and Ni sit slightly below their means. No single chart crosses 3σ. But the pattern is wrong for stainless, and that is the clue.

Separate charts
Fe +2.7σ, Cr −0.9σ, Ni −0.7σ. No point beyond 3σ on any chart.
T² chart
26.5 against a limit of 17.4. Flagged on day 70, the only flag in days 51–80.
Why
Fe gives 78% of the T² value, Cr 19%, Ni 3%. Fe moved without the other two, so look for an Fe source that is not stainless.

T² has a limit of its own: a shift that moves all three elements up together, along their normal correlation, gives a smaller T². So I keep the separate charts and run T² beside them.

Where AI comes in

With all eight rules running on every chart, every day, finding patterns is no longer the hard part. The hard part is the stream of alarms: which one needs action today, which one is a known effect, and who needs to hear about it. That is the job I give to AI.

StepDone byWhat happens
Check the dataAIBefore the rules run, checks the three assumptions above: share below LOD, carry-over between days, correlation between elements. Proposes the chart that fits; code computes it.
Check all 8 rulesCodeEvery chart, every new result. Exact and repeatable, one test per rule.
Sort the alarmsAIReads the flags with the context log (lot changes, maintenance, analyst notes) and sorts them: act now, watch, or likely noise.
Early warningAISends a short warning for "act now" items: which chart, which rule, since when, and the first thing to check.
Draft the recordAIWrites the investigation note in our format, for QA or a customer, in English, Korean or Chinese.
DecideMeConfirms the cause against the chart and the lab, decides the action, signs the record.

On the sample data, if the log showed a new standard lot opened on day 30, the sorting would put the Rule 6 flag on day 34 in "act now", with "compare old and new lot" as the first check. That warning comes 24 days before a limits-only check would say anything.

Limits of this approach

  • The rule check stays in code. In an exploratory study of ChatGPT on SPC tasks, Megahed and co-authors found it handled structured work such as code translation well, but also wrote code that would not run, mixed up less common SPC terms, gave different answers to the same prompt, and described a dataset that does not exist. They advise validating every output. So the model never decides whether a rule fired.
  • The method choice is mine. AI flags when an assumption fails and drafts the code for the alternative. I decide which model to use and check every result against the references below.
  • Sorting is a suggestion. "Likely noise" is not a release decision. Every alarm stays in the log, and a person can open any of them.
  • The data is synthetic. No company or customer data is used anywhere in this note.
